# Common-base practices audit

- **Repo:** `credit-portfolio-early-warning`
- **Catalog id:** `credit-portfolio-early-warning` (package `credit_portfolio_ews`, env prefix `CREDITEWS`)
- **Date:** re-run against the tree after the vertical was implemented (not the day-one render)
- **Catalogue reference:** [`common-base-practices.md`](https://github.com/portable-genai/.github/blob/main/common-base-practices.md) (checks A1..G7)

This file shipped PRE-FILLED with the verdicts the TEMPLATE could honestly claim on render. It has
since been re-run against the tree, row by row, with the vertical in place. Where a row MOVED, the
row says what was observed failing first, because a verdict that was only ever observed green
asserts nothing.

Applicability: a rendered repo ships an `agent/` surface (tool functions plus the A2A card
served at `/.well-known/agent-card.json`), a `ui/` micro-frontend, a full `scripts/` demo
surface and a vertical-neutral `infra/terraform/` deploy posture, so the `[ui]`, `[demo]` and
`[infra]` checks all apply on day one. What `infra/terraform/` does NOT carry is this vertical's
own data-plane resources; adding one means adding its API, its CMEK service-agent binding, its
least-privilege role and its perimeter entry in the same commit. The agent is scaffolded
and tested but not yet registered with `agent-registry`; see the R4 row in `COMPLIANCE.md`. A repo with no
user-facing surface should run `make drop-ui` and mark the `[ui]` rows N/A, rather than leaving
a UI half-wired.
**Load-bearing** checks (a FAIL breaks a shared catalog guarantee) are A1-A6, C1-C5, D1-D3 and E1.

  `policy:` block that is present in the settings file, with an equality test holding the two
  together and a load-time validator refusing an inconsistent block.

  half of it, and the source-dependent treatment of an empty retrieval.

  PASS, because authorisation is by partition key rather than by data tags.
- **A8** stays PARTIAL, but two more horizontals are consumed through thin delegates: `agent-registry` for
  adverse-media retrieval and the model gateway for narration.
- **C11** is a NEW row for this vertical: the read-only grading system of record.

The two remaining GAPs are genuinely per-repo rather than something the template could have
filled in:

- **G3** add `docs/ADOPTING.md` if this repo will itself be forked.
- **G5** add `docs/faq/` (security, compliance, features, portability, adoption).

been deployed: the vertical's own resources, the notification channels, the IAP members, the
